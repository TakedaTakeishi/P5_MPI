Para dar solución al requerimiento de procesamiento de datos, el problema central consistió en procesar múltiples operaciones aritméticas de forma concurrente, cada una dependiente de un conjunto específico de valores flotantes (a, b y c). En lugar de calcular cada operación de manera secuencial, lo cual subutiliza los recursos de hardware, resulta mucho más adecuado abordar este problema empleando MPI. Esta tecnología permite instanciar múltiples procesos de trabajo independientes que pueden ejecutar sus cálculos matemáticos al mismo tiempo, lo que acelera significativamente la obtención de resultados globales.

La estrategia de paralelización adoptada fue un esquema de maestro-esclavo mediante la división de tareas \cite{ref4_frem}. Para este fin, se emplearon exactamente ocho procesos, ya que la carga de trabajo estipula la evaluación de siete operaciones distintas (siete esclavos), requiriendo un proceso adicional que actúe como nodo principal (un maestro). Las responsabilidades se dividieron de la siguiente forma:

\begin{itemize}
    \item \textbf{Proceso 0 (Maestro):} Contiene la matriz de datos completa, los distribuye uno a uno a los demás nodos, y recolecta los resultados para imprimirlos ordenadamente.
    \item \textbf{Procesos 1 al 7 (Esclavos):} Cada uno recibe una fila de datos, ejecuta una fórmula matemática única con dichos valores, y retorna el resultado al maestro.
\end{itemize}

Durante el desarrollo del sistema se emplearon diversas funciones clave de MPI, cuyo uso fue fundamental:
\begin{itemize}
    \item \texttt{MPI\_Init}: Utilizada para inicializar el entorno de ejecución paralelo antes de cualquier operación de red.
    \item \texttt{MPI\_Comm\_rank} y \texttt{MPI\_Comm\_size}: Empleadas para obtener el identificador único (\textit{rank}) de cada proceso y validar que existan exactamente ocho nodos.
    \item \texttt{MPI\_Send} y \texttt{MPI\_Recv}: Funciones punto a punto utilizadas para que el maestro envíe los arreglos numéricos y un token de sincronización, y a su vez, reciba el cálculo procesado por los esclavos de forma segura \cite{ref7_frem}.
\end{itemize}

Por otra parte, dentro del archivo principal escrito en lenguaje C, la inicialización asegura que el programa se abortará de manera limpia si no se proporcionan los ocho procesos requeridos, lo cual previene violaciones de segmento o bloqueos indefinidos. 

El algoritmo se complementa con un pase de tokens (\textit{permiso}) desde el nodo maestro hacia cada esclavo. Este enfoque asegura que los mensajes impresos en la consola aparezcan de forma secuencial, evitando que la salida estándar de los procesos colisione.

Las pruebas del aplicativo se llevaron a cabo utilizando el subcomando \texttt{make run}, el cual despliega la instrucción \texttt{mpirun --mca btl \^{}tcp -np 8 ./main}. Esta configuración de lanzamiento permitió instanciar el ecosistema paralelo de manera local.

Como se puede apreciar en la evidencia visual, el uso de funciones de sincronización aseguró que cada uno de los nodos imprimiera su información de recepción de datos y cálculo en el tiempo adecuado, logrando una consola limpia y comprensible.

En la Figura \ref{fig:salida_mpi} se expone la consola de comandos resultante. El nodo cero (maestro) emite los mensajes de distribución y posteriormente, por turnos, los nodos del uno al siete exhiben la operación realizada junto con la impresión del tiempo actual proporcionado por la herramienta de \texttt{MPI\_Wtime} \cite{ref1_frem}.
